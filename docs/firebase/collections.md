The complete old route-to-domain inventory is in `parity-matrix.json`, checked
by `pnpm firebase:parity:check`. Each planned path needs explicit field schema,
index budget, authorized writer, migration version and fault tests before it is
used by the web app. Firebase Security Rules never authorize Admin SDK calls;
trusted services must recheck policy on every operation.

Feed reference schema version 2 adds `authorUid` for owner-scoped Room history
queries. Disposable version-1 emulator fixtures must be regenerated by the
local seed scripts before Room Memories are tested; no admitted customer data
exists to backfill. The trusted reader compares this key with the canonical
post author after fetching it, so a stale or forged hint cannot expose content.

Memories are derived from canonical posts, Life Updates, and these feed
references; there is no separate Memories collection or copied private body.
Each Firebase web request reads one bounded window per source (50 Box post
candidates, up to 320 Home references, and 20 own Life Updates). The cursor
records source positions and can advance through a window with no visible
items. UTC year/month queries constrain `createdAt` in Firestore. The web
calendar links to periods without exact counts because a live count would
need to scan all accessible, mutable content.

The Box deletion processor removes Box-linked `nativeFeedRefs` and
`nativeNotifications` pointers in bounded batches, then detaches Life Update
deliveries; the final delivery tombstones the canonical content. It leaves
unrelated pointers intact and refuses an unrecognized Box-linked `items`
collection. Malformed or unretirable media still blocks deletion. A
stored intent remains retryable while cleanup waits; the Box stays unreadable.
